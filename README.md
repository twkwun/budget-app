# 가계부

가족이 함께 쓰는 가계부 웹앱(PWA)입니다. 시놀로지 NAS의 Docker에서 실행하고 Tailscale로만 접속합니다. 설계와 단계별 계획은 [docs/DESIGN.md](docs/DESIGN.md)를 보세요.

> 계획한 여섯 단계를 모두 만들었습니다: 로그인·앱 잠금·구성원 초대, 카드·계좌와 분류, 빠른 입력·내역·홈 요약, 카드 결제 문자 자동 등록·자동 분류·인박스, 뱅크샐러드·카드사·은행 파일 가져오기, 예산·고정지출·통계·CSV 내보내기·백업 상태. 실제 기기·실제 문자·실제 파일로 아직 확인하지 못한 것은 맨 아래 [실기기에서 확인할 것](#실기기에서-확인할-것)에 모아 두었습니다.

이 문서의 앞부분은 NAS에 설치하고 가족이 쓰기까지(운영 안내), 뒷부분은 개발자용입니다.

## 1. 배포 (시놀로지 + Tailscale)

GitHub Actions가 `main`에 푸시될 때와 `v1.2.3` 같은 태그를 올릴 때 amd64·arm64 이미지를 만들어 GHCR(`ghcr.io/<소유자>/<저장소>`)에 올립니다. NAS에서는 이미지를 받아 실행만 합니다. 앱 컨테이너 옆의 Tailscale 컨테이너가 tailnet 안에서만 HTTPS로 앱을 열어 주고, NAS의 포트는 하나도 열지 않습니다.

### 1-1. 사전 준비

1. **Container Manager**: DSM 패키지 센터에서 설치합니다. 지원하지 않는 모델이면 이 방식으로는 배포할 수 없습니다.
2. **GHCR 이미지 접근**: 저장소가 공개이면 이미지도 공개로 둘 수 있습니다. GitHub의 Packages에서 이미지 공개 여부를 확인하세요. 비공개로 두면 NAS에서 `docker login ghcr.io`(읽기 권한 토큰)가 필요합니다.
3. **Tailscale**:
   - 관리 콘솔의 DNS 설정에서 **MagicDNS**와 **HTTPS Certificates**를 켭니다.
   - Settings → Keys에서 **Auth key**를 만듭니다. 처음 연결할 때만 쓰입니다.
   - 가족의 모든 기기(아이폰, 아이패드, 맥, PC)에 Tailscale을 설치하고 같은 tailnet에 넣거나, 앱 노드를 공유합니다.

### 1-2. NAS에 폴더 만들기

File Station에서 예를 들어 `docker/budget` 공유 폴더 아래에 다음 구조를 만듭니다.

```
docker/budget/
├ compose.yml           ← docker/compose.example.yml 복사
├ .env                  ← docker/.env.example 복사 후 수정
├ tailscale/
│  ├ serve.json         ← docker/tailscale/serve.json 복사
│  └ state/             ← 빈 폴더 (Tailscale 노드 정보 저장)
└ data/                 ← 빈 폴더 (DB와 backups/)
```

`compose.yml`의 이미지 이름은 `.env`의 `APP_IMAGE`로 바꿀 수 있습니다.

### 1-3. `.env` 작성

`.env.example`의 설명을 따라 채웁니다. 꼭 바꿔야 하는 값:

| 변수                 | 내용                                                                |
| -------------------- | ------------------------------------------------------------------- |
| `TS_AUTHKEY`         | Tailscale auth key                                                  |
| `TS_HOSTNAME`        | 앱 주소의 앞부분 (예: `budget` → `https://budget.<tailnet>.ts.net`) |
| `APP_IMAGE`          | `ghcr.io/<GitHub 소유자>/<저장소>` (소문자)                         |
| `SESSION_SECRET`     | `openssl rand -base64 48`로 만든 임의 문자열                        |
| `PUBLIC_ORIGIN`      | 실제 접속 주소, 예: `https://budget.<tailnet>.ts.net`               |
| `APP_UID`, `APP_GID` | `data` 폴더에 쓸 수 있는 사용자 (아래 1-4)                          |

선택 값: `BACKUP_TIME`(매일 백업 시각, 한국 시간, 기본 `04:00`), `BACKUP_RETENTION_DAYS`(기본 30), `BACKUP_ENABLED`(기본 `true`), `LOG_LEVEL`.

`compose.example.yml`은 앱에 `TRUST_PROXY=true`를 설정합니다. 앱 포트가 Tailscale 컨테이너를 통해서만 열리므로, Tailscale이 넘겨주는 실제 접속 IP(`X-Forwarded-For`)를 믿고 로그인 횟수 제한에 씁니다. 앱 포트를 직접 열어 쓰는 경우에는 `false`로 두세요.

**`PUBLIC_ORIGIN`은 패스키에 묶입니다.** 주소를 바꾸면 모두 패스키를 다시 등록해야 하므로 처음에 정하고 바꾸지 않습니다.

### 1-4. 데이터 폴더 권한

앱 컨테이너는 root가 아닌 사용자로 실행됩니다. SSH로 NAS에 접속해 다음 중 하나를 합니다.

- `data` 폴더 소유자를 1000으로 바꾸기: `sudo chown -R 1000:1000 /volume1/docker/budget/data`
- 또는 `id` 명령으로 확인한 내 계정의 uid/gid를 `.env`의 `APP_UID`, `APP_GID`에 적기

### 1-5. 프로젝트 만들기

1. Container Manager → **프로젝트** → **생성**.
2. 경로로 `docker/budget`을 고르고 "기존 compose.yml 사용"을 선택합니다.
3. 웹 포털 설정은 건너뜁니다 (앱은 Tailscale로만 접속합니다).
4. 완료하면 이미지를 받아 `app`과 `tailscale` 컨테이너가 시작됩니다. `app`이 healthy가 된 뒤 `tailscale`이 시작됩니다.

SSH로 하려면 같은 폴더에서 `sudo docker compose up -d`.

### 1-6. 확인

1. Tailscale 관리 콘솔에 `budget` 기기가 보이는지 확인합니다.
2. Tailscale이 켜진 기기에서 `https://budget.<tailnet>.ts.net/api/health`를 엽니다. `"status":"ok"`가 나오면 됩니다. 첫 접속 때 인증서 발급으로 몇 초 걸릴 수 있습니다.

## 2. 처음 실행

1. `https://budget.<tailnet>.ts.net`을 엽니다. 사용자가 한 명도 없으면 **처음 설정** 화면이 나옵니다(그 뒤로는 다시 열리지 않습니다).
2. 이름, 아이디, 비밀번호를 입력해 **관리자** 계정을 만듭니다.
3. 화면에 나온 **복구 코드**를 종이나 암호 관리 앱에 저장합니다. 다시 볼 수 없습니다.
4. **패스키 추가**로 Face ID·Touch ID를 등록합니다. 아이폰에서 등록하면 iCloud 키체인으로 같은 Apple 계정의 아이패드·맥에도 동기화됩니다.
5. **설정 → 카드·계좌**에서 가족이 쓰는 카드와 통장을 등록합니다. 카드사와 끝 4자리를 넣어 두면 결제 문자와 파일이 자동으로 연결됩니다. 가족카드처럼 명의자와 실제 사용자가 다르면 ‘실제 사용자’를 지정합니다.
6. **설정 → 보안**에서 앱 잠금 시간(즉시·5분·1시간·끔)을 고릅니다.
7. 홈 아래에 "서버 연결됨"이 보이면 준비가 끝났습니다. 관리자를 두 명 두는 것을 권합니다(한 사람이 모든 로그인 수단을 잃어도 다른 관리자가 다시 초대할 수 있습니다).

## 3. 가족 초대와 기기 설치

1. 관리자가 **설정 → 구성원 → 초대 링크 만들기**로 링크(7일, 1회용)를 만들어 가족에게 보냅니다. 받는 사람의 기기도 Tailscale에 연결되어 있어야 합니다.
2. 가족은 링크를 열어 계정을 만들고, 복구 코드를 저장하고, 각자 패스키를 추가합니다.
3. 기기별 설치(홈 화면 앱):
   - 아이폰·아이패드: Safari → 공유 → **홈 화면에 추가**
   - 맥: Safari → 파일 → **Dock에 추가**
   - PC: Chrome·Edge 주소창의 **앱 설치** 아이콘
4. PC에서는 Windows Hello로 패스키를 따로 추가하거나, 로그인 화면에서 패스키 로그인을 누른 뒤 나오는 QR을 아이폰으로 찍어 로그인합니다.
5. 아이폰 Tailscale 앱에서 **VPN On Demand**를 켜 두면 밖에서도 앱과 문자 전달이 끊기지 않습니다.

## 4. 아이폰 단축어로 결제 문자 보내기

카드 결제 문자를 받으면 아이폰 단축어 자동화가 문자 내용을 앱으로 보내고, 앱이 거래로 등록합니다. 앱의 **설정 → 문자 전달**에 복사 버튼과 함께 같은 순서가 나와 있습니다. 구성원마다, 기기마다 따로 설정합니다.

1. **설정 → 문자 전달 → 토큰 만들기**: 기기 이름(예: ‘수진 아이폰’)을 넣고 만듭니다. 본인 재확인 후 토큰이 **한 번만** 보이니 바로 단축어에 붙여 넣습니다.
2. 단축어 앱 → **자동화** → **새로운 자동화** → **메시지** → ‘메시지 내용 포함’에 `승인`(취소 문자도 받으려면 `취소` 자동화를 하나 더) → **즉시 실행**.
3. 동작 **날짜 포맷**: 현재 날짜, ISO 8601, 시간 포함.
4. 동작 **URL 콘텐츠 가져오기**: URL `https://budget.<tailnet>.ts.net/api/webhook/sms`, 방법 `POST`, 헤더 `Authorization: Bearer <토큰>`, 본문 JSON — `text`=단축어 입력의 내용, `sender`=발신자, `receivedAt`=3단계의 포맷된 날짜.
5. **설정 → 문자 전달 → 문자 붙여넣기 테스트**로 우리 카드사의 실제 문자가 어떻게 해석되는지 미리 확인합니다(저장하지 않습니다).

인식하지 못한 결제 문자와 등록되지 않은 카드는 **인박스**에 모이고, 결제 문자가 아닌 문자(인증번호 등)는 저장하지 않고 버립니다. 자세한 규칙은 [결제 문자 처리 규칙](#결제-문자-처리-규칙)에 있습니다.

## 5. 파일 가져오기

**가져오기** 화면에서 뱅크샐러드 내보내기 파일(비밀번호 포함 `.xlsx`)이나 카드사·은행 이용내역 파일(`.xlsx`, `.xls`, CSV)을 올립니다. 미리보기에서 결제수단 연결·분류·중복을 확인하고 **반영**을 눌러야 들어갑니다. 같은 파일이나 겹치는 기간을 다시 올려도 이미 가져온 행은 건너뛰므로, 매달 1년치를 올려도 됩니다. 잘못 가져왔으면 기록에서 **가져오기 취소**로 되돌립니다.

아이폰에서는 메일·메신저로 받은 파일을 **파일 앱에 저장**한 뒤 가져오기 화면에서 고릅니다. 자세한 규칙과 인식하는 열 이름은 [파일 가져오기 규칙](#파일-가져오기-규칙)에 있습니다.

## 6. 예산·고정지출·통계

- **예산**(홈의 예산 카드, 또는 더보기·설정 → 예산): 한 달 **전체 예산**과, 원하면 **상위 지출 분류별 예산**(식비, 쇼핑 등)을 정합니다. 분류 예산에는 하위 분류의 지출이 모두 들어갑니다. 예산은 정한 달부터 다시 바꿀 때까지 매달 그대로 적용되고, 바꿔도 이전 달은 그대로입니다(이월 없음). ‘이 달부터 예산 없애기’로 끌 수 있고, 바꾼 기록은 누가 언제 바꿨는지와 함께 남습니다. 가족 누구나 정할 수 있습니다.
- **진행 표시**: 쓴 금액·남은 금액·비율을 보여 주고, 이번 달에는 막대 위의 세로선이 ‘오늘까지 한 달 중 지난 비율’(한국 시간)입니다. 쓴 비율이 지난 비율보다 10%p 넘게 앞서면 ‘예상보다 빠름’, 예산을 넘으면 빗금 막대와 ‘○원 초과’ 문구로 알려 줍니다(색만으로 구분하지 않습니다). 알림은 앱 안에서만 보입니다(푸시 없음).
- **고정지출**(설정 → 고정지출): 같은 가맹점에서 비슷한 금액(±20%)이 **석 달 이상 연속으로 한 달에 한 번** 나가고 결제일이 일주일 안쪽으로 비슷하면 후보로 제안합니다. ‘등록’하거나 ‘아니에요’로 다시 묻지 않게 하고, 직접 추가할 수도 있습니다. 등록한 고정지출은 홈에 이번 달 상태(결제됨 · 예정 · 아직 없음)로 보이고, 가맹점 이름이 맞고 금액이 ±20% 안인 결제가 들어오면 자동으로 ‘결제됨’이 됩니다. 후보는 ‘나만 보기’ 거래로는 만들지 않습니다. 결제 확인은 각자 볼 수 있는 거래로 합니다.
- **통계**(더보기 → 통계): ‘최근 12개월’ 또는 ‘연도’(작년과 비교 — 올해는 작년 같은 기간과 비교)를 고르고, 가족 전체나 구성원 한 명으로 봅니다. 월별 지출·수입, 분류별 추이, 구성원별 지출(거래의 ‘누구 것’ 기준), 많이 쓴 가맹점을 보여 주며, 그래프마다 같은 내용의 표가 있습니다. 막대나 표의 달·분류를 누르면 그 조건의 **내역**이 열립니다.
- 모든 합계에서 **이체와 취소된 거래는 빠지고**, 다른 가족의 ‘나만 보기’ 거래는 그 사람에게만 보이고 합산됩니다.

## 7. 백업과 복원, 내보내기

### 자동 백업

- 서버가 매일 `BACKUP_TIME`(한국 시간, 기본 04:00)에 SQLite 온라인 백업으로 `data/backups/budget-YYYYMMDDTHHMMSSZ.sqlite`를 만듭니다(파일명 시각은 UTC). 만든 뒤 무결성 검사를 하고, 완성된 파일만 남깁니다.
- `BACKUP_RETENTION_DAYS`(기본 30일)보다 오래된 백업은 지웁니다. 가장 최근 백업은 항상 남깁니다.
- 서버가 시작될 때 최근 24시간 안의 백업이 없으면 바로 하나 만듭니다(NAS가 꺼져 있었던 경우).
- **설정 → 백업·내보내기**(관리자)에서 마지막 백업 시각·크기, 보관 개수, 다음 자동 백업 시각을 보고 **지금 백업**을 누를 수 있습니다. SSH에서는 `sudo docker exec <앱 컨테이너> node dist/cli/backup.js`.
- **Hyper Backup**: `docker/budget/data/backups` 폴더(또는 `data` 전체)를 Hyper Backup 작업에 넣어 NAS 밖에 한 번 더 보관하세요. 실행 중인 `budget.sqlite`보다 `backups/`의 파일이 일관된 사본입니다.

### 복원

1. Container Manager에서 프로젝트를 **중지**합니다(또는 `sudo docker compose stop app`).
2. `data/budget.sqlite`를 다른 이름으로 옮겨 둡니다(`budget.sqlite.before-restore`). 옆의 `budget.sqlite-wal`, `budget.sqlite-shm`도 함께 옮깁니다.
3. 되돌릴 백업 파일(`data/backups/budget-…sqlite`, 또는 Hyper Backup에서 꺼낸 파일)을 `data/budget.sqlite`로 **복사**합니다. 소유자가 앱 사용자(1-4)인지 확인합니다.
4. 프로젝트를 다시 시작하고 `/api/health`가 `ok`인지, 홈의 최근 거래가 맞는지 확인합니다.

백업은 그 시점의 DB 전체(계정·패스키·세션 포함)이므로, 복원 후 그 뒤에 만든 거래·패스키는 없어집니다. 더 새 버전의 앱으로 복원하면 시작할 때 필요한 마이그레이션이 자동 적용됩니다. 반대로 새 버전에서 만든 백업을 옛 버전 앱으로 여는 것은 지원하지 않습니다.

### CSV 내보내기

**설정 → 백업·내보내기 → CSV로 내보내기**에서 기간을 골라 받습니다. 엑셀·넘버스에서 바로 열리는 UTF-8(BOM) 파일이며, 내가 볼 수 있는 거래만 들어갑니다. 내보내기 전에 본인 재확인을 합니다. `=`, `+`, `-`, `@`로 시작하는 글자는 엑셀이 수식으로 실행하지 않도록 앞에 `'`를 붙입니다. 열: 날짜, 시간, 구분, 금액, 가맹점, 대분류, 소분류, 결제수단, 사용자, 상태, 메모, 비공개, 입력 경로.

## 8. 업데이트

Container Manager → 프로젝트 → 해당 프로젝트 → **작업 → 빌드**(이미지 다시 받기) 또는 SSH에서:

```bash
sudo docker compose pull && sudo docker compose up -d
```

- 업데이트 전에 설정 → 백업·내보내기에서 **지금 백업**을 눌러 두세요. DB 마이그레이션은 앱이 시작할 때 자동으로 적용됩니다.
- **설치한 앱(홈 화면 PWA)으로 새 버전이 오는 방식**: 앱은 시작할 때, 백그라운드에서 돌아올 때, 한 시간마다 새 버전을 확인합니다. 새 버전은 뒤에서 내려받아 두고, 화면 아래에 ‘새 버전이 준비됐습니다 · 지금 업데이트’를 띄웁니다(입력 중인 화면을 갑자기 바꾸지 않기 위해). ‘나중에’를 눌러도 앱을 완전히 닫았다 다시 열면 새 버전으로 열립니다. 앱을 연 직후 몇 초 안에 새 버전을 찾으면 묻지 않고 바로 바꿉니다. 캐시를 지우거나 앱을 다시 설치할 필요는 없습니다.
- 지금 어떤 화면 버전인지는 설정 맨 아래 ‘앱 빌드’에, 서버 버전은 홈 맨 아래에 보입니다.

## 9. 문제 해결

- **`tailscale` 컨테이너 로그에 인증 오류**: auth key가 만료됐거나 이미 쓰였습니다. 새 키를 넣고 `tailscale/state`를 비운 뒤 다시 시작합니다.
- **앱이 바로 종료됨**: `app` 로그에 `Invalid configuration`과 함께 잘못된 변수가 표시됩니다.
- **`SQLITE_CANTOPEN` 또는 권한 오류**: 1-4의 데이터 폴더 권한을 확인합니다.
- **로그인할 때 `invalid_origin` 오류, 패스키가 안 됨**: `.env`의 `PUBLIC_ORIGIN`이 실제로 여는 주소와 정확히 같은지(https, 끝에 `/` 없음) 확인합니다.
- **"서버에 연결할 수 없습니다"**: 그 기기의 Tailscale이 꺼져 있습니다. 아이폰은 VPN On Demand를 켜 두세요.
- **비밀번호 로그인이 잠김**: 5번 연속 틀리면 15분 동안 막힙니다(이후 길어짐). 패스키 로그인은 막히지 않습니다.
- **문자가 등록되지 않음**: 설정 → 문자 전달에서 토큰의 ‘마지막 사용’과 ‘무시된 문자’ 수를 봅니다. 무시된 문자가 늘면 문자 붙여넣기 테스트로 형식을 확인하고, 아예 요청이 없으면 단축어 자동화의 ‘즉시 실행’과 Tailscale 연결을 확인합니다.
- **화면이 예전 그대로**: 앱을 완전히 닫았다(앱 전환기에서 위로 밀기) 다시 엽니다. 그래도 같으면 설정 맨 아래 ‘앱 빌드’ 시각과 이미지 업데이트 여부를 확인합니다.
- **패스키·비밀번호·복구 코드를 모두 잃은 경우**: 본인은 되찾을 방법이 없습니다. 다른 관리자가 그 계정을 사용 중지하고 새로 초대합니다. 그 사람의 기존 거래는 그대로 남습니다.
- **잘못 가져온 파일**: 가져오기 → 기록 → ‘가져오기 취소’.
- **DB를 되돌려야 함**: 7장의 복원 순서를 따릅니다.

- [ ] 실제 카드사·은행 이용내역 파일(`.xls`/`.xlsx`/HTML-`.xls`/CSV)의 머리글 인식, 엑셀 암호화 방식

- [ ] 설치된 아이폰 PWA로 새 버전이 오는지: 업데이트 후 앱을 백그라운드에서 다시 열면 ‘새 버전’ 표시, 앱을 완전히 닫고 열면 새 ‘앱 빌드’

## 개발

```
apps/server     Fastify API 서버, Drizzle(SQLite) 스키마·마이그레이션, 백업 작업
apps/web        Vue 3 + Vite PWA (폰은 하단 탭, 아이패드·PC는 좌측 메뉴)
packages/shared 서버·화면 공용 타입, 금액(원)·날짜(Asia/Seoul) 유틸
docker/         Dockerfile, compose 예시, Tailscale serve 설정, .env 예시
e2e/            Playwright 전체 흐름 테스트
```

- 금액은 모두 원 단위 정수입니다.
- 시각은 UTC 밀리초로 저장하고, 날짜·월 경계는 한국 시간(Asia/Seoul) 기준으로 계산합니다 (`packages/shared/src/date.ts`).

### 로컬 개발

준비물: Node.js 22.18 이상, pnpm 10 (`corepack enable`이면 `package.json`의 버전이 자동으로 쓰입니다).

```bash
pnpm install
pnpm dev          # 서버(http://localhost:3000)와 화면(http://localhost:5173)을 함께 실행
```

- 브라우저에서 http://localhost:5173 을 엽니다. 화면 개발 서버가 `/api` 요청을 서버로 넘겨 줍니다.
- 서버는 TypeScript 소스를 Node로 바로 실행하며, 파일을 고치면 다시 시작합니다.
- 개발용 데이터는 `apps/server/data/`에 생깁니다 (git에 올라가지 않음). 지우면 초기화됩니다.
- 서버 설정은 환경 변수로 합니다. 개발 중에는 기본값으로 충분하고, 바꾸려면 `apps/server/.env`를 만듭니다. 변수 목록은 [docker/.env.example](docker/.env.example)에 있습니다.
- 개발 서버(`pnpm dev`)에서는 서비스 워커를 등록하지 않습니다.

구성원 두 명(`demo-sujin` 관리자, `demo-junho` 구성원, 비밀번호 `demo-pass-1234`), 카드·계좌 다섯 개, 최근 2년의 거래, 예산과 고정지출이 생깁니다. 이름·가맹점·금액은 모두 지어낸 것입니다. 실제로 쓰는 DB에는 실행하지 마세요.

### 검사와 테스트

```bash
pnpm lint          # ESLint
pnpm format:check  # Prettier (고치려면 pnpm format)
pnpm typecheck     # 모든 패키지 타입 검사
```

### 사용자 설명서와 버전 이력

- 앱 안의 **사용자 설명서**(`/manual`)와 **버전 이력**(`/changelog`)은 [apps/web/src/manual.ts](apps/web/src/manual.ts)와 [apps/web/src/changelog.ts](apps/web/src/changelog.ts)에 적습니다. 사이드바 아래쪽, 휴대폰은 **더보기 → 도움말**에서 엽니다.
- [docs/user-manual.md](docs/user-manual.md)는 `pnpm manual:md`로 `manual.ts`에서 만듭니다. 직접 고치지 않습니다.
- 화면 캡처(`apps/web/public/manual/*.jpg`)는 `pnpm build && pnpm manual:shots`로 다시 만듭니다. 임시 폴더에 데모 데이터를 넣고 빌드된 서버를 띄워 설치된 Google Chrome으로 찍습니다(`./data`는 건드리지 않습니다). Chrome이 없으면 `MANUAL_BROWSER=chromium`으로 Playwright의 Chromium을 씁니다.
- 버전은 `Major.Minor.Patch`이고 `changelog.ts`의 `APP_VERSION`과 모든 `package.json`의 `version`이 같아야 합니다(테스트가 확인).

### 프로덕션 빌드를 로컬에서 실행

```bash
pnpm build
NODE_ENV=production \
SESSION_SECRET="$(openssl rand -base64 48)" \
PUBLIC_ORIGIN=http://localhost:3000 \
DATA_DIR=./data \
pnpm start
```

http://localhost:3000 에서 빌드된 화면을, http://localhost:3000/api/health 에서 상태를 볼 수 있습니다. `PUBLIC_ORIGIN`은 브라우저 주소창의 주소와 정확히 같아야 합니다.

### Docker 이미지 직접 빌드

```bash
docker build -f docker/Dockerfile -t budget-app:local .
docker run --rm -p 3000:3000 -v "$PWD/data:/data" \
  -e SESSION_SECRET="$(openssl rand -base64 48)" \
  -e PUBLIC_ORIGIN=http://localhost:3000 \
  budget-app:local
```

컨테이너는 `node`(uid 1000) 사용자로 실행되므로 마운트한 폴더에 그 사용자가 쓸 수 있어야 합니다 (`sudo chown 1000:1000 data`).

### DB 스키마 변경

1. `apps/server/src/db/schema.ts`를 고칩니다.
2. `pnpm db:generate`로 `apps/server/drizzle/`에 마이그레이션 SQL을 만들고 함께 커밋합니다.
3. 서버는 시작할 때 아직 적용되지 않은 마이그레이션을 자동으로 적용합니다.

기본 분류(지출·수입 2단계)는 시작할 때마다 빠진 것만 채워 넣습니다. 이름을 바꾸거나 보관 처리한 분류는 건드리지 않습니다.

### PWA 업데이트 구조

`vite-plugin-pwa`가 `sw.js`(Workbox precache)를 만들고, `apps/web/src/pwa.ts`가 등록합니다(`registerType: 'prompt'`). 새 워커는 설치된 뒤 기다리고, ‘지금 업데이트’가 `SKIP_WAITING`을 보내면 넘어가며 `controllerchange`에서 한 번 새로 고칩니다. 기다리는 동안 열려 있는 화면은 이전 버전의 캐시로 계속 동작합니다. 서버는 `index.html`, `sw.js`, manifest를 `no-cache`로, `/assets/*`(해시 파일명)는 1년 캐시로 보냅니다. 이전 빌드의 화면 조각을 못 불러오면 그 주소로 다시 열어 새 빌드를 씁니다.

### 가계부 동작

- **금액**은 원 단위 정수입니다. 거래 유형은 지출·수입·이체이며, **이체(카드대금, 내 계좌 간 이동)와 취소된 거래는 합계에서 빠집니다.** ‘확인 필요’ 거래는 합계에 들어갑니다.
- **날짜**: 거래 시각은 UTC로 저장하고, 날짜와 월은 항상 한국 시간 기준으로 계산합니다. 11월 1일 0시 30분 결제는 기기 시간대와 관계없이 11월 거래입니다.
- **부분 취소**: 금액은 취소 후 남은 금액이고, 원래 금액은 따로 보관합니다(4·5단계에서 자동 수집이 채웁니다). 합계는 남은 금액으로 계산합니다.
- **편집 권한**: 가족 가계부이므로 볼 수 있는 거래는 누구나 고치거나 지울 수 있습니다. 분류도 모두가 함께 관리합니다. 카드·계좌는 누구나 자기 것을 만들 수 있고, 수정·보관은 명의자나 관리자만 합니다(명의자 변경은 관리자만).
- **나만 보기**: 서버는 이미 `나만 보기` 거래를 소유자에게만 보여 주고 합계에도 소유자에게만 넣습니다. 화면에서 켜는 기능은 아직 없습니다.
- **분류 보관**: 분류는 지우지 않고 보관합니다. 상위 분류를 보관하면 그때 활성이던 하위 분류도 함께 보관되고, 상위 분류를 복원하면 함께 보관됐던 하위 분류만 돌아옵니다. 보관된 분류는 새 거래에 쓸 수 없지만 기존 거래에는 그대로 남습니다.
- **예산**: `budgets` 테이블에 (연월, 분류) 행으로 저장하고, 어떤 달의 예산은 분류마다 그 달 이전(포함) 가장 최근 행입니다. 금액 0은 ‘그 달부터 없음’입니다.
- **고정지출**: `recurring_expenses` 테이블. 매칭 키(정규화한 가맹점 이름의 일부), 금액(±20%), 결제일, 상태(후보·등록·제안 안 함), 출처(자동·직접)를 가집니다. 후보 찾기는 고정지출 화면을 열 때와 서버에서 한 시간마다 합니다.

### 로그인과 보안 동작

- **처음 설정**: 사용자가 한 명도 없을 때만 `/setup` 화면이 열립니다. 여기서 만든 계정이 관리자가 되고, 그 뒤로는 다시 열리지 않습니다.
- **로그인**: 패스키(Face ID·Touch ID·Windows Hello)가 기본이고 비밀번호는 대체 수단입니다. 비밀번호를 5번 연속 틀리면 15분 동안 비밀번호 로그인이 막힙니다 (이후 5번마다 2배, 최대 하루). 패스키 로그인은 막히지 않습니다. 로그인 관련 요청은 IP별·아이디별로 횟수가 제한됩니다.
- **복구 코드**: 가입할 때 한 번 보여 줍니다. 아이디 + 복구 코드로 비밀번호를 재설정하면 새 코드가 발급되고, 모든 기기의 로그인이 해제됩니다.
- **세션**: 30일 동안 사용하지 않으면 만료됩니다 (사용할 때마다 연장). 쿠키는 HttpOnly·SameSite=Strict이고, HTTPS에서는 `__Host-` 쿠키에 Secure가 붙습니다.
- **앱 잠금**: 마지막 요청 이후 설정한 시간(5분·1시간)이 지나면 서버가 세션을 잠그고, 패스키나 비밀번호로 풀기 전까지는 데이터를 주지 않습니다. ‘즉시’는 앱이 화면에서 사라지는 순간 잠그며, 그 신호를 놓쳐도 서버가 1분 뒤 잠급니다. ‘끔’은 잠그지 않습니다.
- **본인 재확인**: 패스키 추가·삭제, 비밀번호 변경, 복구 코드 재발급, 구성원 관리 전에는 최근 5분 안에 패스키나 비밀번호로 확인한 적이 있어야 합니다. 없으면 확인 창이 뜨고, 확인 후 원래 작업을 이어서 합니다.
- **화면 가리기**: 앱이 백그라운드로 가면 화면을 가려 앱 전환 화면에 금액이 보이지 않게 합니다.
- **CSV 내보내기**도 본인 재확인이 필요합니다.

### 결제 문자 처리 규칙

아이폰 단축어가 카드 결제 문자를 `POST /api/webhook/sms`로 보내면 서버가 해석해 거래로 등록합니다. 설정 방법은 앱의 **설정 → 문자 전달**에 단계별로 나와 있습니다(URL·헤더·본문 복사 버튼, 문자 붙여넣기 테스트 포함).

- **인증**: 구성원·기기마다 만든 토큰(`Authorization: Bearer bgt_…`)으로만 인증합니다. 토큰은 만들 때 한 번만 보이고 서버에는 해시만 남습니다. 만들 때 본인 재확인이 필요하고, 언제든 폐기할 수 있습니다. 토큰별·IP별로 요청 횟수를 제한하고, 본문은 8KB까지만 받습니다.
- **개인정보**: 카드 결제 문자로 **인식되지 않는 문자(인증번호, 택배 안내, 개인 문자, 지원하지 않는 카드사)는 저장하지 않고 버립니다.** 토큰별로 버린 건수와 마지막 시각만 남아 설정 화면에 ‘무시된 문자 N건’으로 보입니다. 인식된 문자만 원문을 보관합니다.
- **재전송**: 같은 토큰이 같은 문자를 다시 보내면 한 건으로 처리합니다. 단축어가 보내는 `receivedAt`(초 단위)이 같으면 재전송이고, `receivedAt`이 없으면 2분 안에 온 같은 문자를 재전송으로 봅니다. 같은 가게에서 같은 금액을 두 번 결제하면 수신 시각이 달라 두 건으로 남습니다.
- **연도**: 문자에는 연도가 없어 받은 시각의 연도를 쓰고, 그러면 결제가 받은 날보다 이틀 이상 뒤가 되는 경우(1월 1일에 받은 12월 31일 결제) 전년도로 봅니다.
- **카드 매칭**: 카드사와 끝 4자리(가려진 `1*3*` 형식 포함)로 등록된 카드를 찾습니다. 소유자는 토큰 주인이고, 카드에 실제 사용자가 지정돼 있으면 그 사람입니다. 맞는 카드가 없으면 수단 없이 등록하고 인박스에 ‘이 카드 등록’을 띄웁니다. 등록하면 그 카드의 이전 거래가 자동으로 연결됩니다.
- **중복**: 이미 직접 입력한 거래와 같은 결제면 새로 만들지 않고 그 거래에 문자를 연결합니다(DESIGN 6.3: 승인번호 → 같은 수단·금액·±1일 + 가맹점 유사도). 애매하면 인박스에서 고릅니다.
- **취소**: 같은 카드·가맹점의 최근 거래를 찾아 전액이면 취소 처리, 일부면 금액을 줄이고 원래 금액을 보관합니다. 못 찾으면 인박스로 갑니다.
- **다시 해석**: 해석기를 고친 뒤 `pnpm reprocess`(컨테이너에서는 `docker exec <앱 컨테이너> node dist/cli/reprocess.js`) 또는 관리자 API `POST /api/admin/reprocess`로 실패했거나 이전 버전으로 해석된 문자를 다시 처리합니다. 여러 번 실행해도 거래가 중복되지 않습니다.

#### 해석기가 받는 문자 형식 (실제 문자로 아직 확인하지 않음)

실제 문자 샘플 없이, 흔히 보이는 형식을 바탕으로 만든 것입니다. 아래와 다르게 오는 문자는 인박스에 원문과 함께 남으니, **설정 → 문자 전달 → 문자 붙여넣기 테스트**로 확인해 주세요. 공통 규칙:

- 앞의 `[Web발신]`은 있어도 없어도 됩니다. 줄바꿈과 띄어쓰기는 구분하지 않습니다.
- 문자는 **카드사 머리말로 시작**해야 합니다: 카드사 이름 → (선택) `카드`/`체크` → (선택) 끝 4자리 `1234`·`(1234)`·`1*3*` → `승인` / `취소` / `승인취소`.
- 금액은 `12,300원` 형식이어야 합니다. `누적…원`은 금액으로 쓰지 않습니다. 원화 금액 없이 외화(`USD 12.50` 등)만 있으면 인박스로 갑니다.
- 일시는 `MM/DD HH:mm`이어야 하고, **가맹점은 일시 바로 뒤**(같은 줄이나 다음 줄)에 와야 합니다.
- `일시불`이면 할부 없음, `03개월`처럼 오면 할부로 기록합니다. 가려진 이름(`홍*동`)은 무시합니다.
- 금액·일시·가맹점 중 하나라도 못 찾으면 거래를 추측해 만들지 않고 인박스로 보냅니다. `거절`·`실패`가 들어간 문자는 결제가 아니므로 버립니다.

| 해석기 (버전)   | 머리말                                                     | 예시 (값은 지어낸 것)                                                                                              |
| --------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `shinhan-sms@1` | `신한`, `신한카드`, `신한체크`                             | `신한카드(1234)승인 홍*동 12,300원(일시불)11/22 14:05 구름카페강남점 누적1,234,567원`                              |
| `kb-sms@1`      | `KB국민`, `KB국민카드`, `KB국민체크`, `국민카드`, `KB카드` | `KB국민카드1*3*승인` / `홍*동` / `12,300원 일시불` / `11/22 14:05` / `구름카페강남점` / `누적1,234,567원` (줄마다) |
| `samsung-sms@1` | `삼성`, `삼성카드`, `삼성체크`                             | `삼성1234승인 홍*동` / `12,300원 일시불` / `11/22 14:05 구름카페강남점` / `누적1,234,567원`                        |

현대·롯데·하나 등 다른 카드사와 은행 입출금 문자는 아직 지원하지 않아 버려집니다.

#### 자동 분류

DESIGN 6.4 순서대로 적용합니다: ① 가족이 만든 규칙(설정 → 분류 규칙, 위에 있을수록 우선) ② 같은 가맹점에 마지막으로 쓴 분류 ③ 기본 키워드(편의점, 주유소, 배달앱, 잘 알려진 체인 이름 등, 끌 수 있음) ④ 미분류. 가맹점 이름은 띄어쓰기·`(주)`·기호를 빼고 비교합니다. 네이버페이·카카오페이 같은 간편결제는 항상 미분류입니다. 직접 입력할 때도 가맹점만 적고 분류를 비우면 같은 방식으로 분류합니다. 인박스나 거래 수정에서 분류를 고칠 때 ‘앞으로도 이렇게’를 고르면 규칙이 생기고 기존 미분류 거래에도 적용됩니다.

#### 인박스

미분류 거래(가족 전체), 그리고 내가 보낸 문자 중 해석 실패·등록되지 않은 카드·원래 거래를 못 찾은 취소·중복 의심이 한곳에 모입니다. 탭의 숫자는 처리할 항목 수입니다.

### 파일 가져오기 규칙

**가져오기** 화면에서 뱅크샐러드 내보내기 파일이나 카드사·은행의 이용내역 파일을 올리면 미리보기를 보여 주고, ‘반영’을 눌러야 거래가 들어갑니다.

- **읽는 형식**: `.xlsx`(비밀번호가 걸린 것 포함, Excel 2010 이후의 표준 암호화), `.xls`(Excel 97–2003, 비밀번호 없는 것), `.xls`로 저장된 HTML 표, CSV·TSV(UTF-8·UTF-16·EUC-KR/CP949). 파일 이름이 아니라 내용으로 형식을 알아냅니다. 한 파일 최대 10MB, 20,000행.
- **읽지 못하는 것**: 비밀번호가 걸린 `.xls`, Excel 2007의 예전 방식(standard) 암호화 `.xlsx`, `.numbers`, PDF. 비밀번호를 풀어 `.xlsx`로 다시 저장하면 읽을 수 있습니다.
- **안전**: 파일은 별도 작업 스레드에서 메모리·시간 제한(20초)을 두고 읽어 다른 사용자를 막지 않습니다. 수식은 계산하지 않고 저장된 값만 읽으며, 외부 링크는 따라가지 않습니다. 원본 파일과 비밀번호는 저장하지 않습니다.
- **흐름**: 올리기 → (비밀번호) → (열을 못 알아보면 열 지정, 같은 형식은 다음부터 자동) → 미리보기 → 반영. 미리보기는 서버에 24시간 보관되고, 반영하지 않으면 지워집니다.
- **결제수단 연결**: 파일의 결제수단 이름마다 가계부의 카드·계좌(또는 ‘수단 없음’, ‘새로 만들기’)를 고릅니다. 카드사 이름과 끝 4자리로 추천하며, 정한 연결은 다음 가져오기에도 씁니다. 카드에 실제 사용자가 지정돼 있으면 그 사람의 거래가 됩니다.
- **분류**: 파일에 분류(뱅크샐러드 대분류/소분류)가 있으면 이름이 비슷한 우리 분류에 연결해 보여 주고, 고친 연결은 기억합니다. 가져온 거래의 분류는 가족 규칙 → 파일의 분류 → 같은 가맹점의 이전 분류 → 기본 키워드 순으로 정합니다. ‘같은 가맹점의 이전 분류’는 거래 시각 기준이라, 오래된 내역을 가져와도 최근에 정한 분류를 덮어쓰지 않습니다.
- **세 가지 결과**: ‘신규’는 새로 추가, ‘중복’은 문자나 직접 입력으로 이미 있는 거래에 연결(확인됨 표시, 비어 있던 분류·가맹점·수단만 채우고 금액은 바꾸지 않음), ‘확인 필요’는 같은 거래인지 애매해서 하나씩 또는 한꺼번에 정합니다. 날짜만 있는 행은 그날 낮 12시로 기록하고, 중복 판단은 날짜(±1일) 기준이라 문자와도 맞춰집니다.
- **취소·환불**: 음수 금액(뱅크샐러드는 양수 지출)이나 ‘취소’ 표시가 있는 행은 같은 수단·가맹점의 원래 거래를 찾아 전액이면 취소, 일부면 금액을 줄입니다(문자 수집과 같은 규칙). 못 찾으면 ‘확인 필요’에서 고릅니다.
- **이체**: 뱅크샐러드의 ‘이체’ 타입은 그대로 이체로 기록합니다. 은행 거래내역에서 카드대금·본인 이체로 보이는 행은 이체로 제안하고, 한꺼번에 바꿀 수 있습니다.
- **다시 올려도 안전**: 매달 1년치를 겹쳐 올려도 됩니다. 행마다 날짜·시간·금액·가맹점·승인번호(같은 내용의 행은 순번까지)로 지문을 남겨, 이미 가져온 행은 ‘이미 가져옴’으로 건너뜁니다. 가져온 뒤 고치거나 일부러 지운 거래도 다시 생기지 않고, 미리보기에서 건너뛴 행도 다음에 다시 묻지 않습니다. 같은 형식의 파일끼리는 서로 다른 행이 한 거래로 합쳐지지 않으므로, 같은 가게에서 같은 금액을 두 번 결제한 것도 두 건으로 남습니다.
- **가져오기 취소**: 기록에서 ‘가져오기 취소’를 누르면 그 파일로 추가된 거래를 지우고, 연결만 한 거래는 연결을 풀고(채웠던 값 되돌림), 취소 반영도 되돌립니다. 가져온 뒤 직접 고친 거래가 있으면 한 번 더 묻습니다. 문자도 연결된 거래는 지우지 않고 문자 거래로 남깁니다. 취소한 파일은 다시 가져올 수 있습니다.
