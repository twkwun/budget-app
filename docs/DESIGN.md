| 항목 | 내용 |
|---|---|
| 사용 기기 | 아이폰, 아이패드, 맥, PC |
| 사용자 | 가족 (구성원별 계정) |

| 인증 | Face ID 등 생체 인증 지원 |

## 1. 요약

시놀로지 NAS에 올려 가족이 함께 쓰는 가계부 웹앱(PWA)을 만든다. 아이폰·아이패드·맥·PC 어디서든 같은 주소로 열고, Face ID(맥은 Touch ID, PC는 Windows Hello)로 로그인한다.

카드 내역을 API로 당겨오는 서비스(CODEF, 바로빌)는 검토 결과 사업자 대상이거나 유료라 제외했다. 대신 두 경로를 같은 처리 흐름에 연결한다.

1. **결제 문자 자동 전달 (실시간)**: 아이폰 단축어가 카드사 문자를 NAS로 보내고, 서버가 파싱해 자동 등록한다.
2. **파일 대조 (월 1회)**: 뱅크샐러드나 카드사의 엑셀 파일을 올려 빠진 건을 채운다.

어느 경로로 들어오든 중복 없이 한 건으로 합쳐지고, 자동으로 분류된다.

## 2. 내역 수집 방식

### 2.1 API 검토 결과: 제외

| 방식 | 개인 사용 | 이유 |
|---|---|---|
| 오픈뱅킹 (금융결제원) | 불가 | 이용기관으로 등록된 사업자만 사용 |
| 마이데이터 | 불가 | 허가받은 사업자만 사용 |
| 신한·국민·삼성 카드사 오픈 API | 불가 | 제휴 사업자 대상 |
| CODEF | 제외 | 정식 버전은 사업자 정보 등록과 승인이 필요. 개인은 기간·횟수가 제한된 데모만 가능 |
| 바로빌 카드조회 API | 제외 | 유료(카드 1장당 월 5,000~7,000원)이고 사업자번호가 필요 |

**바로빌 카드조회 API 조사 내용** (2026-11-22 공식 문서 기준)

- 방식: 카드사 홈페이지 아이디·비밀번호를 바로빌에 등록하면, 바로빌이 주기적으로 카드사 사이트에서 내역을 수집해 보관하고 API로 조회하게 해 준다.
- 대상: 법인카드와 개인카드 모두 등록 가능. 신한·KB·삼성 포함 12개 카드사 (현대카드는 개인카드 불가).
- 수집 주기: 6시간(04·10·16·22시) 또는 1일(04시). 실시간이 아니다.
- 제공 정보: 승인일시, 승인번호, 승인/취소 구분, 금액, 부가세, 할부, 통화, 가맹점명·사업자번호·업태·주소 등.
- 통신: SOAP. Java, Python, Node.js, .NET, PHP 샘플 제공. 테스트 환경은 무료.
- 요금 (일반회원, 카드번호 1개당 월정액): 승인내역 6시간 주기 7,000원, 24시간 주기 5,000원. 첫 신청 월은 무료. API 연동 회원은 사용량 구간별 계약 단가라 금액이 공개돼 있지 않다.
- 제외 이유: 유료다. 카드 3장 기준 월 15,000~21,000원이 든다. 또한 가입 첫 단계가 사업자번호 입력이고, API 호출마다 회원사 사업자번호가 필수다.

### 2.2 수집 경로

| 경로 | 역할 | 손이 가는 정도 |
|---|---|---|
| 결제 문자 전달 | 결제 직후 자동 등록 | 초기 설정 1회 |
| 파일 대조 | 누락 보충, 계좌 내역, 과거 내역 적재 | 월 1회, 1~2분 |
| 수동 입력 | 현금 등 | 건당 10초 |

두 경로 모두 같은 형식으로 변환해 저장한다. 문자 자동화가 실기기에서 안정적으로 돌지 않으면 파일 대조를 주 경로로 쓴다.

### 2.3 결제 문자 자동 전달

아이폰 단축어의 "메시지를 받을 때" 자동화가 카드사 문자를 NAS 웹훅으로 보낸다.

- 아이폰은 다른 앱의 푸시 알림을 읽을 수 없어 **문자만** 잡힌다. 지금 푸시로 받는 카드는 문자 알림을 켜야 하며, 카드사에 따라 월 이용료가 있을 수 있다. 문자를 켜지 않은 카드는 파일 대조로만 들어온다.
- 밖에서 결제할 때도 전달되려면 아이폰의 Tailscale이 항상 연결돼 있어야 한다. Tailscale의 자동 연결(VPN On Demand)을 켠다.
- 자동화가 확인 없이 실행되는지는 iOS 버전에 따라 달라 실기기 검증이 필요하다.
- 대안: 맥이 주로 켜져 있다면, 아이폰 문자가 맥의 메시지 앱에 동기화되는 것을 이용해 맥에서 새 문자를 NAS로 보내는 작은 프로그램을 둘 수 있다. 맥이 꺼져 있던 동안의 문자도 켜질 때 한꺼번에 처리된다.

### 2.4 파일 대조와 뱅크샐러드

**뱅크샐러드를 쓰는지 물은 이유**

뱅크샐러드는 마이데이터 허가를 받은 무료 자산관리 앱이다. 개인은 쓸 수 없는 공식 금융 API로 모든 카드·계좌 내역을 대신 모아 주고, 그 결과를 엑셀로 내보낼 수 있다. 즉 **개인이 공식 API의 결과물을 간접적으로 얻는 가장 쉬운 통로**다. API 서비스를 제외했으므로 이 경로의 비중이 커졌다.

- 이미 쓰고 있다면: 추가 준비 없이 "데이터 내보내기 → 파일로 받기"로 최근 1년치를 받아 올리기만 하면 된다.
- 쓰지 않는다면: 앱을 설치하고 본인인증 후 신한·국민·삼성을 한 번 연결해야 한다. 금융 정보를 뱅크샐러드라는 회사에 맡기는 것이므로 내키지 않으면 쓰지 않아도 된다.

쓰지 않는 경우에는 카드사 홈페이지에서 이용내역 엑셀을 받아 올리는 방식으로 대체한다. 카드사가 3곳이라 파일도 3개가 된다.

**파일 대조가 하는 일**
- 문자로 들어오지 못한 건 보충
- 계좌 이체·자동이체처럼 카드 알림이 없는 내역 반영
- 앱을 쓰기 전 과거 내역 일괄 적재

뱅크샐러드 파일은 비밀번호가 걸린 엑셀로 이메일 발송되며 "뱅샐현황"과 "가계부 내역" 두 시트로 구성된다. 가족 구성원마다 본인 명의 내역만 나오므로 각자 올린다.

### 2.5 그 외 입력

- 수동 입력: 금액 → 분류 → 저장 (현금 등)
- 캡처·영수증 사진을 AI로 판독하는 기능은 선택 사항 ([11장](#11-확정이-필요한-사항))

## 3. 시스템 구성

```
[아이폰·아이패드]  PWA (홈 화면 앱) ─┐
[맥]             Safari 웹 앱 ─────┤          [시놀로지 NAS - Container Manager]
[PC]             Chrome/Edge 앱 ───┼ Tailscale ┌──────────────────────────────┐
[아이폰]          결제 문자 단축어 ──┘  (HTTPS)  │ tailscale 컨테이너 (HTTPS 종단) │
                                             │   └▶ app 컨테이너             │
                                             │       ├ API 서버              │
                                             │       ├ 수집기 (문자·파일)     │
                                             │       ├ 웹 화면 (정적 파일)    │
                                             │       └ SQLite (공유 폴더 볼륨)│
                                             │ 백업: 매일 덤프 → Hyper Backup │
                                             └──────────────────────────────┘
```

### 3.1 기기별 사용 방식

| 기기 | 사용 방식 | 생체 인증 |
|---|---|---|
| 아이폰 | Safari에서 홈 화면에 추가 | Face ID |
| 아이패드 | Safari에서 홈 화면에 추가 | Face ID / Touch ID |
| 맥 | Safari의 "Dock에 추가" 또는 브라우저 | Touch ID |
| PC | Chrome·Edge의 앱 설치 또는 브라우저 | Windows Hello |

모든 기기에 Tailscale이 설치돼 있어야 한다. 화면은 폭에 따라 달라진다. 폰은 하단 탭, 아이패드·맥·PC는 좌측 메뉴와 넓은 표를 쓴다.

### 3.2 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (서버·화면 공통) | 타입과 파서를 양쪽에서 공유 |
| 서버 | Node.js LTS + Fastify | 가볍고 NAS에서 충분 |
| DB | SQLite (WAL 모드) + Drizzle ORM | 가족 규모에 충분, 파일 하나라 백업 쉬움 |
| 화면 | Vue 3 + Vite + PWA | 네 종류 기기에서 한 벌의 코드로 동작 |
| 생체 인증 | 패스키 (WebAuthn, SimpleWebAuthn) | [4장](#4-로그인과-face-id) 참조 |
| 차트 | ECharts | 도넛·추이 그래프 |
| 엑셀 | SheetJS + officecrypto-tool | 비밀번호 걸린 파일 해제 후 파싱 |
| 배포 | Docker 이미지 + Compose | Container Manager의 프로젝트로 실행 |

NAS에 이미 PostgreSQL을 운영 중이면 DB를 그쪽으로 바꾼다. ORM을 쓰므로 초기에 바꾸는 비용은 작다.

### 3.3 Tailscale 구성

앱 옆에 Tailscale 컨테이너를 하나 붙여서 앱 전용 주소를 만든다 (예: `https://budget.<tailnet>.ts.net`).

- 인증서가 자동 발급·갱신되어 HTTPS가 된다. **패스키와 PWA 설치 모두 HTTPS가 필수**라서 이 구성이 필요하다.
- DSM이 80·443 포트를 쓰고 있어도 충돌하지 않는다.
- NAS의 포트를 인터넷에 열지 않는다.
- 이 주소는 패스키에 묶인다. 주소를 바꾸면 패스키를 다시 등록해야 하므로 처음에 정하고 바꾸지 않는다.

### 3.4 저장소 구조

```
budget-app/
├ apps/
│  ├ server/        API, 수집기, 파서, DB 마이그레이션
│  └ web/           Vue PWA
├ packages/

```

## 4. 로그인과 Face ID

웹앱에서 Face ID를 쓰는 표준 방법은 **패스키**다. 기기의 생체 인증으로 본인을 확인하고, 서버에는 공개키만 저장된다. 얼굴·지문 정보는 기기 밖으로 나가지 않는다.

### 4.1 기능

| 기능 | 동작 |
|---|---|
| 패스키 로그인 | 로그인 화면에서 Face ID 한 번으로 로그인. 비밀번호 입력 없음 |
| 앱 잠금 | 앱을 다시 열거나 일정 시간이 지나면 Face ID로 잠금 해제. 시간은 설정에서 선택 (즉시 / 5분 / 1시간 / 끔) |
| 민감 작업 재확인 | 웹훅 토큰 발급, 데이터 내보내기, 구성원 관리 전에 Face ID 재확인 |
| 화면 가리기 | 앱 전환 화면에서 금액이 보이지 않도록 가림 |

### 4.2 기기 간 사용

- **애플 기기**: 패스키가 iCloud 키체인으로 동기화된다. 아이폰에서 한 번 등록하면 같은 Apple 계정의 아이패드·맥에서도 바로 쓸 수 있다.
- **PC**: Windows Hello로 패스키를 따로 등록한다. 또는 로그인 화면의 QR을 아이폰으로 찍어 아이폰의 Face ID로 로그인한다.
- 한 계정에 패스키를 여러 개 등록할 수 있고, 설정에서 기기별로 확인·삭제한다.

### 4.3 대체 수단

- 첫 가입과 패스키 분실 시를 위해 비밀번호 로그인을 남긴다.
- 가입할 때 복구 코드를 발급한다.
- 로그인 실패 횟수를 제한한다.

### 4.4 한계

- 네이티브 앱이 아니라 웹앱이므로 앱 잠금은 서버 세션을 잠그는 방식이다. 잠긴 동안에는 서버가 데이터를 내주지 않는다.
- 홈 화면에 추가한 PWA에서 패스키가 문제없이 동작하는지는 0단계에서 실기기로 확인한다.

## 5. 가족 사용

- **계정**: 구성원마다 계정과 패스키를 따로 가진다. 역할은 관리자(구성원 초대, 설정 변경)와 구성원 두 가지다.
- **귀속**: 모든 거래와 카드에 "누구 것"인지 기록한다. 홈과 통계에서 가족 전체 합산과 구성원별 보기를 전환한다.
- **수집**: 구성원별로 본인 폰의 문자 전달 토큰과 파일 올리기를 각자 설정한다.
- **가족카드**: 알림과 조회 권한이 카드 명의자 기준으로 달라질 수 있어, 카드별로 실사용자를 지정할 수 있게 한다.
- **예산과 분류**: 가족이 공유한다. 분류 규칙도 공유해서 한 사람이 가르치면 모두에게 적용된다.
- **공개 범위**: 기본은 가족 전체 공개다. 거래별 "나만 보기"는 선택 사항이다 ([11장](#11-확정이-필요한-사항)).
- **Tailscale**: 가족의 기기도 NAS 앱 주소에 접근할 수 있어야 한다. 같은 tailnet에 초대하거나 앱 노드만 공유한다. 요금제의 사용자 수 한도를 확인해야 한다.

## 6. 데이터 설계

### 6.1 주요 테이블

| 테이블 | 역할 | 주요 필드 |
|---|---|---|
| `users` | 구성원 | 이름, 역할, 비밀번호 해시, 잠금 시간 설정 |
| `passkeys` | 등록된 패스키 | 사용자, 공개키, 기기 이름, 마지막 사용 시각 |
| `sessions` | 로그인 세션 | 사용자, 만료, 마지막 생체 확인 시각 |
| `accounts` | 카드·계좌·현금 | 소유자, 종류, 카드사, 끝 4자리, 결제일 |
| `webhook_tokens` | 문자 전달 토큰 | 소유자, 기기 이름, 토큰 해시, 마지막 수신 시각 |
| `transactions` | 거래 내역 | 일시, 금액(원, 정수), 유형, 가맹점, 분류, 수단, 소유자, 상태, 출처, 할부, 승인번호 |
| `raw_records` | 수신 원본 보관 | 출처, 원문, 수신 시각, 처리 상태, 연결된 거래 |
| `categories` | 분류 (2단계) | 이름, 상위 분류, 지출/수입 구분 |
| `category_rules` | 자동 분류 규칙 | 가맹점 패턴, 분류, 우선순위 |
| `import_batches` | 파일 가져오기 이력 | 올린 사람, 형식, 신규/중복/실패 건수 |
| `budgets` | 월 예산 | 연월, 분류, 금액 |

- 거래 `유형`은 지출·수입·이체다. **카드대금 출금과 내 계좌 간 이동은 이체**로 분류해 지출 합계에서 뺀다. 빼지 않으면 카드 사용액이 두 번 잡힌다.
- 원본을 `raw_records`에 항상 남긴다. 파서를 고치면 과거 건을 다시 처리할 수 있다.

### 6.2 처리 흐름

```
결제 문자 ──┬▶ 원본 저장 ▶ 공통 형식으로 변환 ▶ 중복 대조 ▶ 자동 분류 ▶ 등록
엑셀 파일 ──┘                    │
                                 └ 변환 실패 ▶ 인박스에 "확인 필요"로 표시
```

### 6.3 중복 제거

같은 결제가 여러 경로로 들어올 수 있으므로 등록 전에 기존 거래와 대조한다.

1. 승인번호가 있으면 승인번호로 대조
2. 없으면 `수단 + 금액 + 날짜(±1일)`로 후보를 찾고 가맹점명 유사도로 확정
3. 일치하면 새로 넣지 않고 기존 거래에 출처를 추가해 "확인됨"으로 표시
4. 애매한 건은 사용자가 고른다

±1일 여유는 승인일과 매입일이 다를 수 있어서다. 취소 건은 원 거래를 찾아 취소 처리하고, 부분 취소는 금액을 차감한다.

### 6.4 자동 분류

1. 사용자가 만든 가맹점 규칙
2. 같은 가맹점의 직전 분류
3. 기본 키워드 규칙 (편의점, 주유소, 배달앱 등)
4. 해당 없으면 "미분류"로 인박스에 표시

분류를 고치면 "이 가맹점은 앞으로도 이렇게"를 물어 규칙으로 저장한다. 네이버페이·카카오페이처럼 실제 가맹점이 드러나지 않는 건은 미분류로 남긴다.

## 8. 배포와 보안

### 8.1 시놀로지 배포

- GitHub Actions가 이미지를 빌드해 GHCR에 올린다. NAS에서는 받아서 실행만 한다.
- Container Manager의 프로젝트(Compose)로 앱과 Tailscale 컨테이너를 함께 실행한다.
- DB 파일은 공유 폴더에 볼륨으로 연결한다.
- 매일 새벽 DB 덤프를 별도 폴더에 저장하고 30일분을 유지한다. 이 폴더를 Hyper Backup 작업에 포함한다.
- NAS 모델에 따라 CPU 종류가 달라 이미지를 amd64·arm64 둘 다 만든다. Container Manager를 지원하지 않는 모델이면 배포 방식을 다시 정해야 한다.

### 8.2 보안

- Tailscale 안에서만 접근 가능하고, 그 안에서도 로그인이 필요하다.
- 웹훅은 구성원·기기별 토큰으로 인증하고 요청 횟수를 제한한다.
- 카드사 아이디·비밀번호는 받지도 저장하지도 않는다. 카드번호는 끝 4자리만 저장한다.
- 세션 서명 키 같은 비밀값은 `.env`로 주입한다.
- **저장소가 공개 상태다.** 실제 문자, 엑셀 파일, API 응답, DB 파일은 커밋하지 않는다. 테스트 샘플은 값을 바꾼 것만 쓴다. 공개할 이유가 없으면 비공개 전환을 권한다.

## 9. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0. 검증 | 아래 네 가지 확인 | 문자 자동화 사용 여부 확정 |
| 1. 뼈대 | 저장소 구조, DB, Docker 이미지, Tailscale HTTPS, NAS 배포 | 네 종류 기기에서 빈 앱이 열림 |
| 2. 로그인 | 계정, 패스키 로그인, 앱 잠금, 구성원 초대 | 가족이 각자 Face ID로 로그인 |
| 3. 기본 가계부 | 수동 입력, 내역, 분류, 홈 | 수동으로 한 달 써볼 수 있음 |
| 4. 문자 수집 | 웹훅, 신한·국민·삼성 파서, 자동 분류, 인박스 | 결제가 자동 등록됨 |
| 5. 파일 가져오기 | 뱅크샐러드·카드사 엑셀, 중복 제거, 미리보기 | 과거 내역 적재 |
| 6. 예산·통계 | 월 예산, 비교 통계, 고정지출 | |
| 7. 선택 기능 | AI 판독, 나만 보기 등 | 필요할 때 |

**0단계 확인 항목**
1. 아이폰 단축어의 문자 자동화가 확인 없이 실행되는지
2. 홈 화면 PWA에서 Tailscale 주소로 패스키(Face ID)가 동작하는지
3. 시놀로지 모델이 Container Manager를 지원하는지
4. 신한·국민·삼성 결제 문자 샘플 수집 (이름·카드번호를 가린 것)

## 10. 위험 요소

| 위험 | 대응 |
|---|---|
| 문자 알림을 켜지 않은 카드가 실시간으로 안 들어옴 | 파일 대조로 보충. 필요하면 해당 카드만 문자 알림 가입 |
| iOS 업데이트로 단축어·PWA 동작이 바뀜 | 파일 대조가 항상 남아 있음. 비밀번호 로그인 유지 |
| 카드사가 문자 문구를 바꿈 | 원문을 보관하므로 파서 수정 후 재처리 |
| Tailscale 주소 변경으로 패스키 무효화 | 주소를 고정하고, 비밀번호·복구 코드로 재등록 |
| NAS 장애 | 매일 덤프 + Hyper Backup |

## 11. 확정이 필요한 사항

1. **시놀로지 모델명**: Container Manager 지원 여부와 CPU 종류 확인용
2. **가족 구성**: 사용 인원, 각자의 폰 종류, 이미 같은 tailnet에 있는지
3. **문자 알림**: 푸시로만 받는 카드를 문자 알림으로 바꿀지, 파일 대조로만 받을지
4. **뱅크샐러드**: 쓸 의향이 있는지. 없으면 카드사 엑셀로 진행
5. **범위**: 카드만 볼지, 계좌 입출금·현금까지 볼지
6. **맥**: 주로 켜져 있는 맥이 있는지 (문자 전달 대안용)
7. **나만 보기**: 가족에게 보이지 않는 거래가 필요한지
8. **AI 판독**: 파싱 실패 건이나 영수증 사진을 외부 LLM API로 보내도 되는지
9. **저장소 공개 여부**
